# Service Desk — система учёта заявок в техподдержку

Учебная практика, Flutter Web. ПР2 — списки, поиск, фильтрация, пагинация.
ПР3 — формы, валидация, связи между сущностями и сохранение данных между
перезагрузками страницы.

Студент: Казиахмедов Р. Р., группа П-1-23.

## Что это

Клиент службы технической поддержки. Данные хранятся в браузере
(`localStorage` через `shared_preferences`); сервер подключается в ПР4.

## Сущности и связи

| Сущность | Связи |
|---|---|
| **Ticket** — заявка | многие к одному с `TicketCategory`, `Employee` (исполнитель) и `Requester`; многие ко многим с `Employee` (соисполнители) |
| **Employee** — сотрудник поддержки | многие к одному с `Department`; многие ко многим с `TicketCategory` (обслуживаемые категории) |
| **Requester** — заявитель | многие к одному с `Department`; **один к одному** с `ServiceAccount` (учётная запись) |
| **Department** — отдел | один ко многим с `Employee` и `Requester` |
| **TicketCategory** — категория заявок | один ко многим с `Ticket`; многие ко многим с `Employee` |

Как связи отражены в интерфейсе:

* **многие к одному** — выпадающий список (`DropdownButtonFormField<int>`):
  категория, исполнитель и заявитель у заявки, отдел у сотрудника;
* **многие ко многим** — множественный выбор набором `FilterChip` внутри
  собственного `FormField<List<int>>`: соисполнители у заявки,
  обслуживаемые категории у сотрудника;
* **один к одному** — вложенная группа полей: учётная запись
  редактируется прямо в форме заявителя, отдельного экрана у неё нет.

Значением выпадающего списка выбран `int`, а не объект: сравнение объектов
идёт по `==`, и без переопределения `==`/`hashCode` выбранное значение
перестало бы совпадать с элементом списка.

## Возможности

### Из ПР2 — теперь для всех пяти сущностей

* поиск с задержкой 350 мс, фильтры, сортировка по щелчку на заголовке,
  постраничный вывод (10/25/50);
* множественное выделение и удаление выбранных с подтверждением;
* логическое и физическое удаление, показ удалённых и восстановление;
* адаптивная раскладка: до 600 пикселей — карточки и нижняя панель
  навигации, шире — таблица и боковая полоса;
* все условия отбора отражаются в адресе страницы.

### Добавлено в ПР3

* **сохранение между перезагрузками**: `shared_preferences` пишет в
  `localStorage`, у каждой модели есть `toJson`/`fromJson`, устойчивые
  к отсутствующим, `null` и неверно типизированным полям;
* **формы создания и изменения** для всех пяти сущностей — один экран
  на обе операции, различие сводится к тому, передан идентификатор или нет;
* **валидация каждого поля** с показом ошибки под самим полем:
  обязательность, длина строки, диапазон и положительность чисел, формат
  почты, телефона, логина, кода отдела, номера заявки и ФИО;
* **проверка уникальности** номера заявки, адреса почты сотрудника, логина
  и адреса почты заявителя, названия и кода отдела, названия категории —
  ошибка приходит из репозитория и показывается под нужным полем;
* **запрет удаления записи, на которую ссылаются**: приложение сообщает
  о невозможности и называет число связанных записей по каждому виду;
* **каскадное поведение**: выбор категории сужает список исполнителей
  и соисполнителей до сотрудников с нужной компетенцией, а значения,
  выпавшие из списка, снимаются — иначе выпадающий список бросит
  исключение на значении, которого нет среди `items`;
* **предупреждение о несохранённых изменениях** через `PopScope` —
  и на кнопку возврата, и на кнопку «назад» в браузере;
* **смена версии формата данных** не роняет приложение: ключ хранилища
  содержит версию, записи прошлой версии стираются, пользователь получает
  об этом сообщение.

Пример адреса:

```
/tickets?search=принтер&categoryId=5&priority=high&sort=dueAt,asc&page=2&size=25
```

## Общие конструкции

Пять сущностей не означают пятикратного повторения кода. Общими являются:

| Конструкция | Файл | Что берёт на себя |
|---|---|---|
| `StoredRepository<T>` | `repositories/stored_repository.dart` | чтение и запись хранилища, выдача идентификаторов, оба вида удаления, проверка уникальности и ссылок |
| `ListNotifier<T, Q>` | `state/list_notifier.dart` | состояние списка: условия отбора, выборка, выделение, изменяющие операции |
| `EntityListPage<T, Q>` | `widgets/entity_list_page.dart` | экран списка целиком |
| `EntityForm` + `FieldSpec` | `widgets/form/` | описание полей списком, разметка, проверка, отправка |
| `DetailPage<T>` | `widgets/detail_page.dart` | карточка записи |
| `ListQuery<Q>` | `models/list_query.dart` | договор условий отбора |

Форма описывается списком описаний полей, а рисует и проверяет их общий
виджет:

```dart
SelectFieldSpec(
  name: 'assigneeId',
  label: 'Исполнитель',
  emptyLabel: '— не назначен —',
  options: (values) => [
    for (final e in reference.employeesForCategory(values['categoryId'] as int?))
      (value: e.id, label: e.fullName, description: e.position),
  ],
)
```

## Запуск

```bash
flutter pub get
flutter run -d chrome --web-port=5555
```

Порт задан явно: по умолчанию `flutter run` выбирает случайный, и адрес
источника меняется от запуска к запуску.

Проверки:

```bash
flutter analyze
flutter test
flutter build web
```

Учебный сбой хранилища включается кнопкой со значком жучка в панели
инструментов: следующий запрос завершается исключением — так проверяется
состояние ошибки.

## Структура

```
lib/
  main.dart                    — точка входа: хранилище, репозитории, провайдеры
  app.dart                     — MaterialApp.router, темы, локаль
  core/
    router.dart                — маршруты: список, создание, карточка, изменение
    breakpoints.dart           — точки перелома по ширине окна
    formatting.dart            — форматы дат, цвета меток, склонения
    validators.dart            — проверки полей, общие для всех форм
    exceptions.dart            — ошибки хранилища, уникальности и ссылок
    fault_switch.dart          — учебный переключатель отказа хранилища
  models/
    entity.dart                — договор записи и безопасный разбор JSON
    ticket.dart, employee.dart, requester.dart,
    department.dart, category.dart, service_account.dart
    enums.dart, page_result.dart
    list_query.dart            — общий договор условий отбора
    *_query.dart               — условия отбора пяти сущностей
  data/
    seed_data.dart             — начальный набор данных
    collection_store.dart      — localStorage и хранилище в памяти для тестов
  repositories/
    crud_repository.dart       — договор доступа к данным
    stored_repository.dart     — общая реализация
    *_repository.dart          — договор и реализация каждой сущности
    app_repositories.dart      — сборка репозиториев и связей между ними
  state/
    load_status.dart, list_notifier.dart, detail_notifier.dart,
    reference_data_notifier.dart
  screens/
    <сущность>_list_screen.dart, _detail_screen.dart, _form_screen.dart
    not_found_screen.dart
  widgets/
    app_shell.dart, entity_list_page.dart, detail_page.dart,
    entity_table.dart, entity_card_list.dart, pagination_bar.dart,
    debounced_search_field.dart, filter_fields.dart,
    status_views.dart, confirm_dialog.dart
    form/
      field_spec.dart          — описания полей формы
      entity_form.dart         — общий виджет формы
      entity_form_screen.dart  — каркас экрана формы с PopScope
      form_loader.dart         — загрузка записи до построения формы
```

Границы слоёв: виджет обращается к данным только через notifier, notifier
не знает про `BuildContext` и виджеты, модель не знает ни про кого.
Интерфейс репозитория объявлен отдельно от реализации, чтобы в ПР4
подменить локальное хранилище на реализацию поверх API, не трогая экраны.
